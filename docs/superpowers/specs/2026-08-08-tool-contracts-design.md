# LocalMind 工具契约与调用防错设计

## 目标

让模型不会在所有工具中盲目猜测：工具先按问题筛选，再由模型规划，程序校验工具和参数；调用失败时最多自动修复一次。以后新接入的 MCP 工具如果没有契约，不进入模型可调用列表，但仍可在工具中心显示为“待配置”。

## 设计

### 工具契约

每个工具包含用途、适用场景、禁止场景、意图关键词、参数规则、调用示例和失败恢复说明。已知工具通过统一契约表注册；未知 MCP 工具默认标记为未配置。

### 候选筛选

用户问题进入模型前，按契约中的关键词和排除词筛选候选工具。若没有匹配工具，则不向模型暴露工具，直接走知识库回答。时间查询优先匹配 `get_current_time`，时区转换只匹配 `convert_time`。

### 调用校验

调用前检查工具 ID、启用状态、必填参数、未知参数和基础 JSON 类型。校验失败不执行工具。

### 失败恢复

对于已识别工具的参数校验失败，向模型发送一次包含错误原因和原始请求的修复提示；修复后的请求再次执行校验。未知工具、未配置工具和第二次失败不会继续重试。

### 新工具接入规则

注册新本地工具或 MCP 工具时，必须同时添加契约映射和测试；未添加契约的 MCP 工具仅展示，不会进入模型工具目录。

## 验收标准

- 天气问题不会把时间工具列为候选。
- “上海几点了”只会调用 `get_current_time` 并填充 `Asia/Shanghai`。
- 缺少必填参数时不直接执行，能进行一次修复。
- 未配置的新 MCP 工具不会被模型调用。
- 现有工具调用和全量测试保持通过。

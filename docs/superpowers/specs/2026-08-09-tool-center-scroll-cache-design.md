# 工具中心滚动、简介与 MCP 缓存设计

## 目标

修复工具中心在工具数量或 MCP 参数说明较长时无法正常浏览的问题，并让 MCP 工具在启动时直接显示上次成功发现的结果，而非再次启动外部 MCP Server。

## 范围

本次只修改工具中心与 MCP 工具发现的展示、缓存和触发时机；不改变已有 MCP Server 配置格式的核心字段，也不改变模型调用 MCP 工具的协议。

## 交互设计

### 中部工具列表

- 搜索、筛选和“管理 MCP Server”保持固定在顶部。
- 工具卡片区域使用独立滚动容器，鼠标位于卡片或空白处时滚轮都驱动该容器。
- 水平滚动条关闭；卡片按现有三列网格自适应排列。

### 右侧工具详情

- 工具名称、状态、简介、能力、示例、参数 schema、最近调用记录和测试结果放入独立的垂直滚动内容区。
- “测试调用”保持在右侧面板底部，不随长说明移出可视区域。
- 本地能力不显示测试按钮；已接入且可调用的工具显示测试按钮。

### MCP 工具简介

- 新发现的 MCP 工具首次保留 MCP Server 返回的名称和简介，保证用户能先完整理解工具能力。
- 工具详情提供“编辑显示信息”：可为每个 Server 下的每个工具单独保存中文显示名称与简短简介。
- 一旦保存显示信息，卡片与详情页优先显示用户维护的文本；原始说明保留为未编辑时的默认值和技术参考。
- 原始参数 schema 保持不变，用于参数验证和实际 MCP 调用。
- 未配置契约的工具仍可展示，但用“尚未配置调用边界”的简短说明替代原始大段描述，并保持不可被模型调用。

## MCP 发现缓存

- 成功执行 MCP 发现后，将可展示工具的最小快照写入本地状态目录。
- `ToolRegistry` 初始化时读取快照，结合当前启用的 Server 配置恢复工具卡片，因此打开工具中心不会启动 `npx`、MCP Server 或网络请求。
- 用户在“管理 MCP Server”中保存或删除配置后，才在后台重新发现启用的 Server，并用结果覆盖快照。
- 如果某个 Server 此次发现失败，不丢弃其他成功结果；失败信息仅用于当前界面提示。
- 配置被删除或禁用后，对应快照工具不会再恢复。

## 数据边界

- 新增独立缓存文件，不向现有 `mcp_servers.json` 写入工具 schema 或运行记录。
- 缓存条目包含 Server ID、工具 ID、原始名称与简介、用户覆盖的显示名称与简介、能力、参数 schema、契约与来源，足以在离线启动时渲染工具中心。
- 真正调用 MCP 工具时仍以当前 `MCPServerDefinition` 为准；缓存仅用于展示和启动期可见性。

## 验收与测试

- 工具列表滚动区和详情滚动区均可被定位，且禁用水平滚动。
- 详情面板的测试按钮不在滚动内容区内，始终可见。
- 已知天气和时间 MCP 工具显示简短中文简介，不显示原始超长说明。
- 刚构造的 `ToolRegistry` 可从缓存恢复工具且不调用 `discover()`。
- 保存/删除 MCP 配置后的刷新仍调用发现流程并更新缓存。
- 现有工具筛选、测试调用和本地能力区测试保持通过。

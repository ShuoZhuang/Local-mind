# 对话知识库选择与证据联动设计

## 设计定位

这是 LocalMind 本地知识助手对话工作台的一次交互增强。目标是在不改变本地运行和现有深色视觉语言的前提下，让用户明确控制本次对话使用哪些知识库、快速定位某条回复的证据，并让工具调用成为低干扰的过程记录。

## 设计决策

### 1. 知识库选择作用于当前会话

对话页面右上角增加三点菜单。菜单列出全部知识库，每项可勾选，并提供“全选/取消全选”操作和当前选择数量。至少保留一个知识库，避免用户提交空检索。

选择结果保存到当前会话。新会话继承创建时的当前选择；已有旧会话仍通过原有 `knowledge_base_id` 字段兼容读取，读取后转换为单元素选择列表。

### 2. 多知识库检索

一次查询使用选中的知识库分别检索，合并结果后按相似度降序排序，并保留稳定的同分排序。检索结果的引用记录增加知识库标识和名称，供右侧回答依据展示。模型仍只接收排序后的 Top-K 片段，不改变本地模型调用方式。

### 3. 来源与回答依据联动

每条助手回复下方显示独立的可点击来源行。来源行绑定该条回复自己的 citations 集合；点击后只更新右侧回答依据面板，右侧显示被点击回复的文档、知识库、相似度和片段预览。首次检索仍可以把最新引用显示到右侧，但点击历史来源后必须切换到对应引用。

### 4. 工具调用展示

工具调用保留在对话时间线中，但不再使用消息气泡。改为透明背景的轻量状态行，使用左侧细色线、工具名、表达式和结果文本表达调用过程。它不参与用户/助手气泡的宽度和对齐逻辑，也不产生额外的圆角卡片层。

### 5. 动效边界

项目是 PySide6 桌面应用，不引入 React 或 GSAP 依赖。将 GSAP 技能中的克制动效、时间线和性能原则映射到 Qt：菜单使用原生弹出，右侧依据切换只使用短时 `QPropertyAnimation`；不在消息滚动或模型流式输出过程中创建高频动画。

## 数据流

```text
三点菜单选择知识库
        ↓
当前 ChatSession 保存 knowledge_base_ids
        ↓
问题提交
        ↓
分别检索选中知识库并合并排序
        ↓
生成带知识库信息的 citations
        ↓
助手回复 + 可点击来源行
        ↓
点击来源行 → 右侧回答依据显示该回复的 citations
```

## 受影响的代码边界

- `app/models.py`：为会话增加可持久化的多知识库选择，并兼容旧数据。
- `app/services/storage.py`：保存和加载会话选择，保持旧 JSON 可读取。
- `app/services/retrieval.py`：增加多知识库检索与合并排序能力。
- `app/services/chat.py`：接受知识库 ID 列表，并为引用补充知识库信息。
- `app/ui/chat_page.py`：添加三点菜单、来源点击信号和非气泡工具行。
- `app/ui/context_panels.py`：显示来源所属知识库并支持被选回复的依据刷新。
- `app/ui/main_window.py`：连接菜单选择、会话持久化、检索参数和右侧面板。
- `app/ui/theme.py`：提供菜单、来源行和工具状态行的深色样式。
- `tests/`：覆盖旧会话兼容、多知识库检索、菜单选择、来源映射和工具行样式。

## 错误处理

- 选择的知识库已被删除时，加载会话时过滤不存在的 ID；如果全部失效，回退到当前可用知识库。
- 某个知识库检索失败时记录该库失败并继续检索其他已选知识库，只有全部失败才向用户显示错误。
- 没有引用时不显示可点击来源行，右侧保持明确的空状态。
- 工具调用失败仍显示失败结果，但不影响后续助手回复。

## 验收标准

1. 三点菜单能列出所有知识库，支持多选、全选和取消全选，并显示选择数量。
2. 发送问题后只检索已选知识库；引用能显示来源知识库。
3. 关闭并重新打开会话后，知识库选择保持不变；旧单知识库会话可以正常打开。
4. 点击任意一条回复的来源行，右侧回答依据切换到该条回复对应的引用，不会显示其他回复的内容。
5. 工具调用显示为透明状态行，不再使用用户或助手气泡样式。
6. 原有单知识库对话、文档导入、模型预热、删除和现有测试不回归。

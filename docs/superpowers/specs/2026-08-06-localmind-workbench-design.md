# LocalMind 工作台界面设计

## 目标

将 LocalMind 重构为统一的深色三栏知识工作台。对话与知识库管理共用稳定的页面骨架，但各自保持清晰的主任务和右侧上下文。

## 视觉方向

- 场景：个人学习与本地资料管理的 Windows 桌面应用。
- 风格：深色、专业、克制、长期使用舒适。
- 主题：全应用固定深色，不出现白色内容面板。
- 强调色：薄荷绿，仅用于当前选中项、主操作和成功状态。
- 圆角：容器 12px，按钮与输入控件 10px。
- 层级：应用底色、普通面板、悬浮面板三层深灰表面；以对比和细边框区分，不用重阴影。
- 密度：中等偏高。阅读区域保留呼吸空间，列表和控制项保持紧凑。

## 全局框架

```text
左侧导航栏 | 中间主工作区 | 右侧上下文栏
```

### 左侧导航栏

- 显示品牌、模型选择、对话和知识库入口。
- 显示知识库列表与最近对话。
- 同一时刻只高亮一个活动对象：当前对话或当前知识库。
- 右键菜单提供重命名和删除。
- 新建对话初始名为“新对话”，首轮回答完成后使用首个问题的前若干字自动命名。

### 中间主工作区

- 只承载用户当前的主任务。
- 对话模式：消息流与输入框。
- 知识库模式：知识库概况、搜索、文档列表和添加文档入口。

### 右侧上下文栏

- 对话模式：显示本次回答实际使用的 Top 3 检索片段与来源。
- 知识库模式：显示选中文档的详情、原文和分块结果。
- 支持收起；收起后中间工作区自动扩展。
- 小窗口下以右侧抽屉形式打开，避免挤压中间内容。

## 知识库管理

### 默认状态

中间区域显示知识库名称、文档数、分块数、搜索栏、添加文档按钮和文档列表。右侧显示当前知识库概览或当前选中文档。

### 导入流程

```text
选择文件 -> 查看文件信息 -> 设置分段策略 -> 预览预计分块数
-> 点击“确认处理” -> 分阶段处理 -> 自动展示结果
```

选择文件后不得自动处理。导入设置显示在右侧上下文栏，主区域仍保留当前文档列表。

### 分段策略

- 自动分段：依据段落和句子组合。
- 按层级分段：优先保留标题和正文的结构关系。
- 自定义分段：支持以下分段标识符：换行、两个换行、中文句号、中文逗号、英文句号、英文逗号、中文问号、英文问号、自定义。
- 选中“自定义”时展示输入框，允许填写实际分隔符，例如 `###`。
- 所有策略都能设置最大分段长度、重叠比例和清洗规则。

### 处理状态

进度使用明确阶段，而不是只显示“处理中”：

```text
读取文档 -> 提取文本 -> 文本分段 -> 生成向量 -> 写入知识库 -> 完成
```

每个阶段显示名称、进度和可见的状态变化。失败时保留文档记录、显示原因并提供重新处理。完成时自动选择该文档并显示分块。

### 文档详情

- 文档名、来源路径、格式、大小、处理时间。
- 当前分段策略与参数。
- “原文预览”和“分块预览”两个视图。
- 分块列表显示序号、长度、正文摘要，支持展开。
- “重新处理”和“删除文档”为次级危险操作，删除前必须确认。

## 对话体验

### 无知识库时

模型可以正常聊天；右侧显示未关联知识库和选择入口。

### 知识库为空时

模型可正常聊天；界面明确提示当前知识库没有可检索资料。

### 有资料时

每次问题先检索本地向量库，再将相关片段提供给本地模型生成回答。回答下方显示“已参考 N 段资料”或“未使用知识库”。点击该状态会展开或聚焦右栏的引用内容。

### 输入规则

- Enter 发送。
- Ctrl + Enter 换行。
- 空输入时发送按钮禁用。
- 生成中发送按钮显示“停止生成”。

### 引用上下文

右栏显示本次实际检索的 Top 3 文本片段、来源文件、相似度及完整上下文入口。用户能从片段回到来源文档。

## 状态、动效与可访问性

- 页面切换：160ms 淡入和最多 8px 位移。
- 右栏：180ms 展开与收起。
- 列表新增：完成后一次性轻微高亮。
- 控件反馈：悬停调整颜色或边框，按下最多下移 1px。
- 不使用无限装饰动画、强发光或大面积渐变。
- 系统偏好减少动画时，所有过渡即时完成。
- 动画仅作用于透明度与位移，不影响布局计算和后台任务。

## 错误与加载

- 不支持格式：在导入设置中说明支持范围。
- 解析失败：显示原因、保留记录、可重新处理。
- 向量模型加载中：禁用确认处理并显示准备状态。
- Chroma 写入失败：明确说明写入失败，不将文档标成完成。
- 回答失败：保留问题和检索片段，提供重新生成。
- 空知识库、空对话和空检索都提供清晰入口，不留大块空白。
- 启动时预热已选模型。模型驻留显存或内存后，后续对话不重复加载。

## 实现边界

- 桌面端使用 PySide6 和 Qt 原生动画，不引入 GSAP。GSAP 的角色仅是动效原则参考，因为它是网页 JavaScript 库。
- 文档解析、分段、向量化、Chroma 写入和模型推理均在后台工作线程执行。
- UI 线程只负责显示状态和接收安全的跨线程信号。
- 保留已有本地模型、Embedding、Chroma 及资料存储结构，改造重点是页面结构、交互状态和稳定性。

## 验收标准

1. 全应用保持深色层次，无白色内容面板。
2. 左栏任一时刻只高亮一个对象。
3. 上传后必须点击“确认处理”才开始。
4. 自定义分段预设完整，选择“自定义”会显示分隔符输入框。
5. 对话右栏能展示该回答的真实检索依据。
6. 导入任务显示真实阶段，结束后关闭进度状态并更新文档状态。
7. 模型加载、文档处理和向量写入不阻塞界面。
8. 首次模型加载有明确状态，后续不会重复加载同一模型。

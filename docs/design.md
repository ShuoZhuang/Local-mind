# 本地知识库 Agent 设计说明

## 目标

构建一个可双击启动的 Windows 桌面 Agent，采用 A「双栏工作台」布局：左侧是导航、多个知识库、模型切换和对话历史，右侧是对话流或知识库管理。所有模型、文档、向量和聊天数据都保存在本机，不调用云端大模型 API。

## 用户流程

1. 启动应用后进入对话页。
2. 在左侧新建或选择一个知识库栏目，例如“人工智能学习”或“模电笔记”。
3. 在知识库管理页上传 TXT、Markdown、PDF 或 DOCX。
4. 应用提取文本、按段落切分、生成本地 Embedding，并写入当前知识库专属的 Chroma collection。
5. 用户可以新建对话；对话记录显示在左侧，并记住使用的知识库和模型。
6. 用户发送问题，应用把问题转换为向量，在当前知识库中检索相关片段。
7. 当前选中的本地模型根据问题和检索片段流式生成回答。
8. 回答下方展示引用的文件名和片段，便于用户判断答案依据。

## 技术方案

- 桌面端：PySide6 + QSS，使用 QThread/worker 避免模型推理阻塞界面。
- 对话模型：Transformers 加载 Qwen2.5-1.5B-Instruct；首次运行下载到本地模型目录，后续从本地加载。自动使用 CUDA，否则使用 CPU。
- 模型注册：`ModelRegistry` 从本地 JSON 读取模型条目，界面使用下拉框切换；新增模型只需增加注册条目，不改聊天界面。
- Embedding：`intfloat/multilingual-e5-small`，查询使用 `query:` 前缀，文档使用 `passage:` 前缀。
- 向量库：Chroma PersistentClient，数据写入 `data/chroma_db`。
- 文档解析：PyMuPDF 处理 PDF，python-docx 处理 DOCX，原生读取 TXT/Markdown。
- 配置：通过 `config.json` 指定模型名、路径、检索数量和生成参数；默认不启用网络 API。

## 界面结构

左栏：

- Agent 名称和状态指示；
- 新建对话；
- 对话历史；
- 知识库入口；
- 当前文档数量、索引状态和模型状态。

右栏：

- 顶部标题和当前知识库状态；
- 用户消息和 Agent 消息气泡；
- 流式输出中的“正在生成”状态；
- 回答引用来源；
- 底部多行输入框、发送按钮和上传按钮。

知识库页：

- 拖拽/选择文件；
- 文件列表、处理进度、切片数量和错误信息；
- 删除文档并同步删除其向量；
- 返回对话页。

## 数据边界

- 原始上传文件复制到 `data/documents`。
- 每个知识库拥有独立的状态记录、原始文件子目录和 Chroma collection；切换知识库不会混用检索结果。
- 切片元数据包括文档 ID、文件名、路径、页码（若有）、切片序号和导入时间。
- Chroma 只保存切片文本、Embedding 和元数据。
- 会话历史保存为本地 JSON，不上传网络。
- 首次下载模型需要网络；模型下载完成后可通过离线配置运行。

## 失败处理

- 文件格式不支持或文本为空时，在知识库页显示明确错误，不写入半成品索引。
- 模型未下载时显示下载/加载状态，不阻塞窗口启动。
- 模型加载失败时保留检索功能，并在对话区提示具体原因。
- 没有检索到足够相关内容时，回答必须说明“知识库中没有找到充分依据”，不伪造引用。
- 用户重复上传同一文件时按文件哈希更新，不产生重复切片。

## 第一版验收标准

- 从 `G:\trial_project\004` 启动应用并看到双栏界面。
- 可以导入至少一个 TXT/Markdown 文件并显示索引完成。
- 重启应用后文档和向量仍然存在。
- 输入问题后能返回流式回答，并显示引用文件。
- 全流程不需要 API Key；除首次下载模型外不需要网络。
- `001` 项目文件和运行结果不发生变化。
